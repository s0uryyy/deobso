## Автоматические тесты

`./gradlew -p tests test` проверяет реальный общий код Java:

- строгую проверку UUID (включая опасный случай `1-1-1-1-1`);
- Ctrl-политику преобразования и пустое поле;
- round-trip обычных и кастомных offline-аккаунтов, чтение старого v1;
- различение одинаковых ников с разными UUID;
- чтение трёх допустимых уровней папки без изменения файла/живого списка;
- отсутствие создания файлов в пустом источнике;
- дубликаты, выборочный импорт, откат живого списка при ошибке сохранения;
- повреждённое хранилище и ограничение распакованного размера;
- отсутствие открытых Ely.by tokens в сериализованном аккаунте.

Не используй реальные аккаунты для тестовых fixtures и не добавляй account storage
в Git. Тестовые файлы создаются только в JUnit TempDir.

## Ручной smoke test для каждого JAR

1. Чистая копия игрового каталога, оригинальный IAS удалён, установлены зависимости
   нужного загрузчика. Открыть меню аккаунтов, проверить бренд и отсутствие
   наложения новой кнопки на список/поиск (GUI Scale 2/3/4).
2. Добавить offline: пустой UUID, корректный UUID, uppercase UUID, 32 hex, мусор,
   пробелы. Неверный UUID должен блокировать и Done, и Enter без Ctrl.
   Проверить левый/правый Ctrl, отпускание, Alt для неправильного ника.
3. Войти offline, сверить **UUID сессии**, перезапустить игру, повторить.
   Проверить два аккаунта с одинаковым ником и разными UUID.
4. Выбрать другую папку через navigation/ручной путь (Windows: также другой диск).
   Отменить до/после сканирования, изменить размер окна во время чтения.
   Отметить несколько аккаунтов на разных страницах, импортировать, повторить.
   Проверить счётчик, пропуск дубликатов и неизменность источника (hash/mtime).
5. Импорт: пустая папка, плохой путь, нет разрешений, битый файл, незнакомый тип,
   password/hardware-encrypted аккаунты, источник=назначение, отказ записи.
6. Без injector: offline и Microsoft должны работать; Ely.by Add заблокирован.
7. В отдельном профиле с injector: пароль скрыт, 2FA пустой/верный/неверный,
   ошибка сети, Cancel во время входа не должен добавлять аккаунт.
   Проверить повторный вход, перезапуск, refresh, истёкший/отозванный токен.
8. Сверить скин Ely.by в меню и мире, повторить на сервере с поддержкой Ely.by.
   Проверить поведение отсутствующего скина. Не ожидать Ely.by-входа на обычном
   Mojang online-mode сервере. Microsoft Add/Login с injector должны блокироваться.

## Известные границы

- Нет автономного skin-provider: требуется javaagent.
- Нет горячего переключения Ely.by ↔ Microsoft.
- Нет архивных 1.7–1.12 и произвольных форматов сторонних лаунчеров.
- Формат новых аккаунтов не читается оригинальным IAS, поэтому deobso работает только со своей копией папки.
- Hardware-encrypted токены не гарантируют переносимость на другой ПК.
- Матрица сборок и соответствие внешнего injector каждой версии пока не проверены.

## Artifact storage quota в GitHub Actions

Обычные push/PR-проверки больше не загружают HTML-отчёты как artifacts:
сводка JUnit выводится в Job Summary, детали выполнения остаются в логах Gradle.
При ручном запуске `deobso checks` можно включить `upload_reports`.
Неудача этой необязательной загрузки не меняет результат самих тестов.

Полная матрица теперь сохраняет JAR, отдельные SHA256SUMS и логи каждой цели в
общий черновик Releases. Загрузка в Actions Artifacts для неё не используется.
Сначала отдельно проверяется Fabric 1.21.11, затем остальные 44 цели. Публикации
публичного релиза не происходит. Если сборка цели не удалась, сохраняется её лог,
но JAR не создаётся. Успех проверяй по статусу job и наличию JAR в Assets.

Fabric 1.21.11 успешно собран и загружен в запуске
https://github.com/s0uryyy/deobso/actions/runs/34767352142 (commit `3ff5b7b`).
Остальные задачи этого запуска на момент обновления документации ещё выполняются.

Эти настройки не освобождают уже занятую квоту. Если квота исчерпана, владелец
аккаунта может удалить ненужные artifacts в Actions своих репозиториев либо
изменить лимиты/тариф. После удаления GitHub может пересчитывать использование
6–12 часов. Не путай artifacts с dependency caches. Старые artifacts автоматически
этим изменением не удаляются.


## Браузерный OAuth и нативный выбор папки

- Ely.by → браузер открывается автоматически. Пароль/2FA только на сайте, повторное
  открытие браузера использует тот же запрос, Try again — новый. Отмена, выход с
  экрана, отказ на сайте и 5-минутный тайм-аут не добавляют аккаунт. Проверить
  firewall и повторное открытие экрана, вход без запущенного agent (добавление
  разрешено, игровой вход требует agent), обновление OAuth-токена после перезапуска.
- Проверить Tiny File Dialogs на Windows/Linux/macOS: Cancel оставляет исходное
  меню, выбранная папка сразу сканируется, но ничего не импортируется без выбора
  и подтверждения. Ошибка нативной библиотеки даёт ручной ввод пути. Проверить
  кириллицу/пробелы/другие диски, выбор пустой/повреждённой папки и отсутствие
  графического окружения. Нативный диалог модальный и вызывается на UI-потоке.
- OAuth-тесты не используют реальные Ely.by credentials и не обращаются к сети

Исторические проверки PKCE выше относятся к предыдущей версии. Новый экран
запускает Device Authorization, не localhost-callback. Проверить вручную:

- Получение кода, автоматическое открытие браузера, повторное открытие, копирование
  кода, подтверждение на сайте, отказ, тайм-аут, отмена и повторная попытка.
- Экран Ely.by: рамка/фон/заголовок как у Microsoft, перенос строк статуса,
  кнопки браузера/копирования/Back; смена языка и GUI Scale.
- Импорт: ванильная кнопка, полноценный JFileChooser в системной теме,
  кнопка «Открыть», видимость скрытых папок, путь с кириллицей, другой диск,
  отмена и закрытие окна. Проверить Windows/Linux/macOS; Java-диалог не является
  нативным Windows IFileDialog, но заменяет старое дерево TinyFD.
- В окружениях без java.desktop/графической сессии должен остаться ручной ввод пути.

возвращает HTTP verification_uri, поэтому мод нормализует только известный
адрес на HTTPS. Результат этой проверки не равен проверке входа в аккаунт.

## Упаковка 1.01-newgen

`python3 -m unittest discover -s dev/tests -v` проверяет имена файлов,
отсутствие конфликтов между загрузчиками, SHA256 и отклонение некорректной
версии внутри Fabric JAR. `package_build.py` проверяет `fabric.mod.json`
готового JAR перед загрузкой. Матрица объединяет временные артефакты
в один `deobso-newgen-v1.01` и удаляет их после успешного объединения.
Логи доступны в jobs Actions, но отдельными артефактами не загружаются.

## ElyPrismLauncher replacement authlib regression

The runtime detector accepts the game's resolved session implementation with an
integrated ElyProfileService from the same code source, without a javaagent.
Tests reject vanilla session fixtures, unrelated helper classes, and an empty
class loader. CI verifies the exact 7.0.61-ely.1 library's checksum and field
structure without executing its code. This is not a live ElyPrism game test.

The completed matrix must have exactly one `deobso-newgen-v1.01` artifact.
Separate optional test-report artifacts are disabled; logs/reports remain in
Actions job output. All successful target JARs and checksums are merged together.
