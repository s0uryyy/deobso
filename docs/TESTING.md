## Что удалось проверить в рабочей среде

- Синтаксический разбор новых и изменённых Java-классов (Tree-sitter).
  Это **не компиляция** и не проверка Minecraft API.
- Соответствие наличия экранов всем 11 legacy source sets и текущему source set.
- Сохранение пути аккаунтов и наличия readers прежних типов аккаунтов.
- Gradle wrapper запущен на установленной Java 25, но загрузка
  `https://services.gradle.org/distributions/gradle-9.7.1-bin.zip` завершилась
  `SSLHandshakeException: Remote host terminated the handshake`.
- Java unit tests добавлены, но **не выполнялись**: Gradle недоступен.
- Minecraft не запускался; Ely.by не проверялся с реальными учётными данными.

## Автоматические тесты

`./gradlew -p tests test` проверяет реальный общий код Java:

- строгую проверку UUID (включая опасный случай `1-1-1-1-1`);
- Ctrl-политику преобразования и пустое поле;
- round-trip обычных и кастомных offline-аккаунтов, чтение старого v1;
- различение одинаковых ников с разными UUID;
- чтение трёх допустимых уровней папки без изменения файла/живого списка;
- отсутствие создания файлов в пустом источнике;
- дубликаты, выборочный импорт, откат живого списка при ошибке сохранения;
- повреждённое хранилище и ограничение распакованного размера;
- отсутствие открытых Ely.by tokens в сериализованном аккаунте.

Не используй реальные аккаунты для тестовых fixtures и не добавляй account storage
в Git. Тестовые файлы создаются только в JUnit TempDir.

## Ручной smoke test для каждого JAR

1. Чистая копия игрового каталога, оригинальный IAS удалён, установлены зависимости
   нужного загрузчика. Открыть меню аккаунтов, проверить бренд и отсутствие
   наложения новой кнопки на список/поиск (GUI Scale 2/3/4).
2. Добавить offline: пустой UUID, корректный UUID, uppercase UUID, 32 hex, мусор,
   пробелы. Неверный UUID должен блокировать и Done, и Enter без Ctrl.
   Проверить левый/правый Ctrl, отпускание, Alt для неправильного ника.
3. Войти offline, сверить **UUID сессии**, перезапустить игру, повторить.
   Проверить два аккаунта с одинаковым ником и разными UUID.
4. Выбрать другую папку через navigation/ручной путь (Windows: также другой диск).
   Отменить до/после сканирования, изменить размер окна во время чтения.
   Отметить несколько аккаунтов на разных страницах, импортировать, повторить.
   Проверить счётчик, пропуск дубликатов и неизменность источника (hash/mtime).
5. Импорт: пустая папка, плохой путь, нет разрешений, битый файл, незнакомый тип,
   password/hardware-encrypted аккаунты, источник=назначение, отказ записи.
6. Без injector: offline и Microsoft должны работать; Ely.by Add заблокирован.
7. В отдельном профиле с injector: пароль скрыт, 2FA пустой/верный/неверный,
   ошибка сети, Cancel во время входа не должен добавлять аккаунт.
   Проверить повторный вход, перезапуск, refresh, истёкший/отозванный токен.
8. Сверить скин Ely.by в меню и мире, повторить на сервере с поддержкой Ely.by.
   Проверить поведение отсутствующего скина. Не ожидать Ely.by-входа на обычном
   Mojang online-mode сервере. Microsoft Add/Login с injector должны блокироваться.

## Известные границы

- Нет автономного skin-provider: требуется javaagent.
- Нет горячего переключения Ely.by ↔ Microsoft.
- Нет архивных 1.7–1.12 и произвольных форматов сторонних лаунчеров.
- Формат новых аккаунтов не читается оригинальным IAS, поэтому deobso работает только со своей копией папки.
- Hardware-encrypted токены не гарантируют переносимость на другой ПК.
- Матрица сборок и соответствие внешнего injector каждой версии пока не проверены.

## Artifact storage quota в GitHub Actions

Обычные push/PR-проверки больше не загружают HTML-отчёты как artifacts:
сводка JUnit выводится в Job Summary, детали выполнения остаются в логах Gradle.
При ручном запуске `deobso checks` можно включить `upload_reports`.
Неудача этой необязательной загрузки не меняет результат самих тестов.

Полная матрица по умолчанию проверяет сборку без сохранения JAR. Для скачивания
результатов включи `upload_jars` при ручном запуске. В этом режиме ошибка загрузки
по-прежнему видна как ошибка job: успешная компиляция не гарантирует наличие JAR
для скачивания. Новые артефакты хранятся 3 дня.

Эти настройки не освобождают уже занятую квоту. Если квота исчерпана, владелец
аккаунта может удалить ненужные artifacts в Actions своих репозиториев либо
изменить лимиты/тариф. После удаления GitHub может пересчитывать использование
6–12 часов. Не путай artifacts с dependency caches. Старые artifacts автоматически
этим изменением не удаляются.
