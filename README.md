# deobso account changer

Форк [In-Game Account Switcher](https://github.com/The-Fireplace-Minecraft-Mods/In-Game-Account-Switcher)
на основе commit `8cdd44342c9832b26a3bd6292222cfdf2d1dbfea`.
Лицензия **LGPL-3.0-or-later**, авторство upstream сохранено в `NOTICE` и исходниках.

> **Статус: исходники для проверки, не проверенный релиз.** В этой среде загрузка
> Gradle блокируется ошибкой TLS; компиляция, Java-тесты и запуск Minecraft пока
> не подтверждены. JAR-файлы не приложены. Полная поддержка перечисленных версий
> должна быть подтверждена сборочной матрицей и игровыми проверками.

## Возможности

- Исходные возможности IAS: Microsoft-аккаунты, offline-вход, список аккаунтов.
- **Add accounts from folder** в меню аккаунтов: встроенный в игру выбор папки
  (навигация и ввод пути), затем отдельный выбор аккаунтов, Select all / Clear
  selection и Import selected. Ничего не импортируется до подтверждения.
- При первом обращении к аккаунтам папка оригинального IAS
  `_IAS_ACCOUNTS_DO_NOT_SEND_TO_ANYONE` **целиком копируется** в
  `_DEOBSO_ACCOUNTS_DO_NOT_SEND_TO_ANYONE`. Далее мод читает и записывает только
  эту отдельную рабочую копию, включая уведомления и отметку их прочтения.
  Оригинал не переименовывается и не изменяется. Если папка deobso уже существует,
  копирования/слияния не происходит. Без папки IAS создаётся новое хранилище deobso.
  При ошибке копирования неполная копия не становится рабочей папкой; запись в
  оригинал как запасной вариант не производится.
- Импорт читает выбранную папку, не вызывает миграцию и не записывает в источник.
  Можно выбрать корень другой игры, папку `_IAS_ACCOUNTS_DO_NOT_SEND_TO_ANYONE`,
  `_DEOBSO_ACCOUNTS_DO_NOT_SEND_TO_ANYONE` или их `.hidden`. Если в корне игры
  есть обе папки, импорт выбирает deobso; для IAS выбери его папку явно. Поддерживается бинарное хранилище IAS с типами offline v1/v2,
  Microsoft v1 и типами этого форка. Произвольные форматы сторонних лаунчеров и
  старые JSON-хранилища не поддерживаются.
- Дубликаты пропускаются. Аккаунты с одинаковым ником и разными кастомными UUID
  различаются. Зашифрованные данные переносятся без расшифровки: hardware-bound
  аккаунт с другого компьютера может потребовать повторного добавления;
  password-encrypted Microsoft-аккаунту потребуется прежний пароль хранилища.
- В offline-форме есть поле **UUID**. Пустое поле — стандартный offline UUID.
  Нормальный формат: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`, шестнадцатеричные цифры.
  Неверный формат блокирует Done и Enter; **Ctrl** разрешает принудительное
  добавление. 32 hex-символа нормализуются дефисами; другая строка преобразуется
  в стабильный name-based UUID. Произвольная строка не может быть UUID Minecraft.
  Валидация ника и обход через Alt оставлены от IAS.
- Отдельный тип **Ely.by**, вход по логину/e-mail и паролю с необязательным кодом
  2FA, обновление сессии. Пароль не сохраняется, токены шифруются механизмом IAS
  HardwareCrypt v2. Для скинов и сессий нужен **authlib-injector**, см. [ELY.md](docs/ELY.md).

## Ограничения Ely.by

Это **не автономная реализация скинов в одном mod JAR**: интеграция использует
внешний javaagent. Его нужно настроить в лаунчере. Вход Ely.by не даёт доступ к
обычным серверам с Microsoft/Mojang online-mode. В профиле с Ely.by javaagent
Microsoft-вход в моде блокируется: для него нужно перезапустить игру без agent.
Одновременное переключение двух провайдеров без перезапуска не реализовано.
Отображение скинов зависит от версии injector, клиента и настроек сервера;
скин произвольного offline UUID не гарантируется.

## Версии и загрузчики

Унаследована общая матрица upstream, изменения экранов внесены во все её
варианты. На каждую комбинацию нужен **отдельный JAR**, не один универсальный:

| Minecraft | Загрузчики |
| --- | --- |
| 1.18.2, 1.19.2, 1.19.4 | Fabric, Forge |
| 1.20.1, 1.20.2, 1.20.4, 1.20.6 | Fabric, Forge, NeoForge |
| 1.21.1, 1.21.3, 1.21.4, 1.21.5, 1.21.8, 1.21.10, 1.21.11 | Fabric, Forge, NeoForge |
| 26.1.2, 26.2 | Fabric, Forge, NeoForge |

Точная конфигурация: `stonecutter.properties.json`, исключения:
`dev/versions/ignored.txt`. Архивные ветки IAS 1.7–1.12 и промежуточные версии,
которых нет в этой матрице, **не перенесены**.

Сохранён внутренний mod ID `ias` для совместимости конфигурации. **Не устанавливай
оригинальный IAS рядом с этим форком.** Старый IAS не понимает новые типы
`deobso:offline_v3` и `deobso:ely_v1`, но они теперь записываются только в
отдельную папку deobso. Оригинальная папка IAS сохраняется как исходная копия.
Это однократное копирование, а не синхронизация и не история резервных копий.
Не отправляй никому ни одну из папок: обе содержат учётные данные.

## Сборка и тесты

Нужны JDK 17 / 21 / 25 для соответствующих целевых версий и доступ к Maven/Gradle.

```sh
# Изолированные тесты общего Java-кода (без загрузки Minecraft)
./gradlew -p tests test

# Пример одной комбинации (Stonecutter может также включить текущую VCS-версию)
./gradlew -Dru.vidtu.ias.only=1.21.1-fabric assemble

# Вся унаследованная матрица, включая legacy-версии
./gradlew -Dru.vidtu.ias.legacy=true assemble
```

Артефакты сборки собираются в `build/libs/` средствами upstream.
GitHub Actions активированы в `.github/workflows/`: `build.yml` запускает
core-тесты на push/PR (сводка без загрузки artifacts), а `matrix.yml` позволяет
вручную проверить сборку всех комбинаций. Для сохранения JAR включи `upload_jars`
при ручном запуске; по умолчанию скачиваемые JAR не сохраняются.
Наличие workflow не означает успешной сборки: результаты проверяй во вкладке
Actions и в проверках PR. [План игровых проверок](docs/TESTING.md).

Оригинальная документация сохранена в [UPSTREAM_README.md](docs/UPSTREAM_README.md).
